  - Windows gotchas that look like "ffmpeg is broken" but are not: (1) **fontconfig is unconfigured** — `drawtext=font=Arial` dies with `Fontconfig error: Cannot load default config file` and an access violation (exit `-1073741819`); always pass an explicit `fontfile=`. (2) The **drive colon in `fontfile=C:/...` breaks filter parsing** (`No option name near '/Windows/...'`) and `C\:` is eaten by argv unescaping; the reliable fixes are to copy the .ttf next to the media and use a bare relative `fontfile=arial.ttf` (Push-Location into the workdir), or put the filter in a file and pass `-/filter:v <file>`. (3) `-filter_script:v` was **removed** in ffmpeg 8/9 — it errors `Unrecognized option`; the replacement is the `-/filter:v` read-from-file prefix. (4) `Remove-Item "$dir\*"` on a `%TEMP%` scratch dir is blocked by the harness sandbox as a protected path — make a fresh `ffmpeg-e2e-$(Get-Random)` dir instead of clearing one. (5) `$env:VAR` does not survive between PowerShell tool calls (only the cwd does) — re-derive scratch paths each call.

## Scope rule of thumb

- Prefer documenting “what good looks like” (first-run acceptance items) over large rewrites when the engine already works; the current structural ceiling is one large embedded game+UI page, so later changes remain more brittle than in a separated spine.
- Verification/playtest passes report with a first-line `GRADES spec= design= correctness= quality=; biggest gap:` and grade harshly: correctness only from behavior actually exercised (unexercised caps at 6), design ≤5 while the app stays one/two files; leave a dated per-pass record in `docs/`.
